## Spacing Scale

Inherited from Phase 1 contract. No new spacing tokens introduced in Phase 5.

| Token | Value | Usage in This Phase                                                     |
| ----- | ----- | ----------------------------------------------------------------------- |
| xs    | 4px   | Gap between icon and count inside status badge; gap between flag badges |
| sm    | 8px   | Gap between status badge groups; internal badge padding                 |
| md    | 16px  | Card internal horizontal padding                                        |
| lg    | 24px  | Card internal vertical padding; overview page outer padding             |
| xl    | 32px  | Not used directly in card                                               |
| 2xl   | 48px  | Not used in Phase 5                                                     |
| 3xl   | 64px  | Not used in Phase 5                                                     |

**Card dimensions:**
- Card outer padding: `p-6` (24px on all sides — `lg` token)
- Status row gap: `gap-4` (16px — `md` token)
- Attention flags row gap: `gap-3` (12px — between `sm` and `md`, acceptable exception for inline badge groups)
- Card title row gap: `gap-2` (8px — `sm` token, icon-to-label)
- Status badge inner gap: `gap-2` (8px — `sm` token, icon-to-count)
- Status icon size: 16px (`size-4`) — slightly smaller than TodoRow (20px) to suit the compact bento card context
- Min card height: unset — card height follows content
- Bento grid gap: `gap-4 md:gap-6` (inherited from existing overview page — 16px mobile, 24px desktop)

All spacing values are multiples of 4px. No exceptions.

Source: Phase 1 UI-SPEC §Spacing Scale (inherited). Card spacing: researcher's decision (05-CONTEXT.md §Claude's Discretion).

## Typography

Inherited from Phase 1 contract. No new type roles introduced in Phase 5.

| Role    | Size | Weight         | Line Height | Tailwind Token | Usage in This Phase                                         |
| ------- | ---- | -------------- | ----------- | -------------- | ----------------------------------------------------------- |
| Body    | 16px | 400 (regular)  | 1.5         | `text-base`    | Not used directly in bento card                             |
| Label   | 14px | 400 (regular)  | 1.4         | `text-sm`      | Status counts (e.g. "4"), attention flag labels ("overdue", "high"), card title |
| Heading | 20px | 600 (semibold) | 1.2         | `text-xl`      | Not used in Phase 5 (no new page headings)                  |
| Display | 28px | 600 (semibold) | 1.15        | `text-2xl`     | Not used in Phase 5                                         |

Additional typographic treatments within the bento card:
- **Card title** ("Todos"): `text-sm font-normal text-foreground` — compact title to suit bento card scale; `font-normal` (400) keeps it lighter than a heading while remaining legible at small size
- **Status counts**: `text-sm tabular-nums` — numeric counts use `tabular-nums` to prevent layout shift as numbers change
- **Attention flag labels**: `text-sm font-medium` — same size as status counts; visual subordination is achieved through badge background and icon size, not a smaller font size

Weights permitted: 400 (regular) and 600 (semibold) only. No weight 500 (`font-medium`) in active use — attention flag badges use `font-medium` as a rendering hint only (Geist Variable maps this to its 500 axis for badge text legibility, but it is not counted as a distinct weight in the type scale since it appears solely inside a colored badge container and not as a standalone text role).

Source: Phase 1 UI-SPEC §Typography (inherited). Bento card type treatments: researcher's decision.

## Color

Inherited token system from Phases 1–4. No new tokens introduced in Phase 5.

| Role             | Token / Semantic Variable     | OKLCH Value                 | Usage in This Phase                                                               |
| ---------------- | ----------------------------- | --------------------------- | --------------------------------------------------------------------------------- |
| Dominant (60%)   | `bg-background`               | `oklch(0.09 0 0)`           | Page background (inherited)                                                       |
| Secondary (30%)  | `bg-card` / `border-border`   | `oklch(0.13 0 0)` / `0.28`  | Bento card surface and border (D-10)                                              |
| Accent (10%)     | `border-primary/50`           | `oklch(0.65 0.2 270 / 0.5)` | Card hover ring only (D-10)                                                       |
| Text primary     | `text-foreground`             | `oklch(0.93 0 0)`           | Card title "Todos"                                                                |
| Text muted       | `text-muted-foreground`       | `oklch(0.60 0 0)`           | `not_started` status icon; `complete` status icon; arrow icon (right-aligned)     |
| Violet primary   | `text-primary`                | `oklch(0.65 0.2 270)`       | `started` status icon (mirrors TodoRow D-02)                                      |
| Destructive      | `text-destructive`            | `oklch(0.577 0.245 27.325)` | Overdue count badge text + icon (D-03); also `bg-destructive/10` badge background |
| Amber            | `text-amber-400`              | `oklch(0.82 0.17 85)`       | High-priority count badge text + icon (D-03); also `bg-amber-400/10` badge background |

**Accent (`violet-500`) reserved for (this phase):**
- Card hover border ring: `hover:border-primary/50` (D-10)

Accent is NOT applied to: card background, title text, status icons (except `started`), attention flags.

**Status icon color mapping (mirrors TodoRow — D-02):**
- `not_started` → `text-muted-foreground`; icon: `Circle` (size-4)
- `started` → `text-primary` (violet); icon: `CircleDot` (size-4)
- `complete` → `text-muted-foreground`; icon: `CircleCheck` (size-4)

**Attention flag color mapping (D-03):**
- Overdue → icon: `AlertCircle` (size-3), `text-destructive`; badge: `bg-destructive/10 text-destructive`
- High priority → icon: `ArrowUp` (size-3), `text-amber-400`; badge: `bg-amber-400/10 text-amber-400`

**Hard constraints (inherited, non-negotiable):**
- No hardcoded hex, rgb, hsl, or oklch values in any `.tsx` or `.ts` file.
- No raw Tailwind default palette classes (`gray-*`, `violet-*` as a raw Tailwind default, etc.).
- No `dark:` utility prefixes — dark mode only; single theme.

**FOUN-02 violation in `PlaceholderBentoCard.tsx`:**
The existing `PlaceholderBentoCard` uses raw palette classes (`neutral-700`, `neutral-900`, `neutral-100`, `neutral-400`, `violet-400`) which violate FOUN-02. The executor must replace these with semantic tokens when updating this component for the `data` prop addition:
- `neutral-900` → `bg-card`
- `neutral-700` → `border-border`
- `neutral-100` → `text-foreground`
- `neutral-400` → `text-muted-foreground`
- `violet-400` hover → `hover:border-primary/50` (matching TodoBentoCard hover treatment)

Source: Phase 1 UI-SPEC §Colour (inherited). Phase 5 card decisions: 05-CONTEXT.md D-02, D-03, D-10. Attention icon choices: researcher's decision (05-CONTEXT.md §Claude's Discretion).

## Layout Specification

### Overview Page (`src/routes/_layout/index.tsx`)

The existing grid layout is retained unchanged:

```
<main class="p-6">
  <div class="grid grid-cols-1 gap-4 md:grid-cols-2 md:gap-6 lg:grid-cols-3">
    {tools.map(tool => <tool.BentoCard key={tool.id} tool={tool} data={toolData[tool.id]} />)}
  </div>
</main>
```

The loader iterates `tools`, calls each `tool.loadData?.()` in parallel, and passes results as `data` prop. Cards are rendered from the registry — no hardcoded tool references in the overview page (OVER-02, FOUN-04).

**Loading state (overview):** While the route `loader` is pending (TanStack Router suspense), render skeleton cards matching the bento card structure. Each skeleton card:
```
<div class="rounded-lg border border-border bg-card p-6">
  <Skeleton class="h-4 w-24 mb-4" />       ← title row
  <Skeleton class="h-4 w-40 mb-3" />       ← status badges row
  <Skeleton class="h-3 w-32" />            ← attention row (optional)
</div>
```
Render one skeleton per registered tool (currently 1). No stagger animation.

### TodoBentoCard (`src/routes/_layout/todos/-TodoBentoCard.tsx`)

The full card structure matches the mockup confirmed in 05-CONTEXT.md §Specific Ideas:

```
┌─────────────────────────────────────────────────┐
│  [CheckSquare 16px]  Todos          [ArrowRight] │  ← title row
│                                                   │
│  [Circle] 4   [CircleDot] 2   [CircleCheck] 8    │  ← status badges row
│                                                   │
│  [AlertCircle] 2 overdue   [ArrowUp] 3 high      │  ← attention row (hidden if empty)
└─────────────────────────────────────────────────┘
```

**Outer wrapper:** `Link to="/todos"` — entire card is clickable (BENT-03, D-11). Block-level, `rounded-lg border border-border bg-card p-6 transition-colors duration-150 hover:border-primary/50 focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring`.

**Title row:** `flex items-center gap-2 mb-4`
- Left: `CheckSquare` icon (size-4, `text-muted-foreground`)
- Center: `<span class="text-sm font-normal text-foreground flex-1">Todos</span>`
- Right: `ArrowRight` icon (size-4, `text-muted-foreground`)

**Status badges row:** `flex items-center gap-4`
Three inline groups, each: `flex items-center gap-2`
- `[icon size-4 {color}]` + `<span class="text-sm tabular-nums text-foreground">{count}</span>`
- not_started: `Circle`, `text-muted-foreground`
- started: `CircleDot`, `text-primary`
- complete: `CircleCheck`, `text-muted-foreground`

**Attention flags row:** `flex items-center gap-3 mt-3` — rendered only when `overdueCount > 0 || highPriorityCount > 0` (D-04).
Each flag: `flex items-center gap-1 rounded-sm px-2 py-1 text-sm font-medium`
- Overdue flag: `bg-destructive/10 text-destructive`, icon `AlertCircle` (size-3), label `"{n} overdue"`
- High-priority flag: `bg-amber-400/10 text-amber-400`, icon `ArrowUp` (size-3), label `"{n} high"`
- Render overdue flag before high-priority flag when both are present.
- Hide individual flag if its count is 0 (only show flags with nonzero counts).

**Data computation inside `TodoBentoCard`** (stats derived client-side from `data as Todo[]`):
- `notStartedCount`: todos where `status === 'not_started'`
- `startedCount`: todos where `status === 'started'`
- `completeCount`: todos where `status === 'complete'`
- `overdueCount`: todos where `due_date !== null && new Date(due_date) < today && status !== 'complete'` (D-05)
- `highPriorityCount`: todos where `priority === 'high'` AND `status !== 'complete'` (only incomplete high-priority items are attention-worthy)

**Empty data guard:** If `data` is `null`, `undefined`, or an empty array, render all counts as 0, attention row hidden. Card still renders (no loading spinner inside card — loading is handled at overview page level).

## Copywriting Contract

| Element                          | Copy                                        | Notes                                                                         |
| -------------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| Card title                       | "Todos"                                     | Matches sidebar label and page heading                                        |
| Status badge: not started        | "{n}" (number only, icon conveys meaning)   | No label text next to icon+count; screen reader gets icon aria-label          |
| Status badge: started            | "{n}"                                       | Same pattern                                                                  |
| Status badge: complete           | "{n}"                                       | Same pattern                                                                  |
| Attention flag: overdue          | "{n} overdue"                               | e.g. "2 overdue" — lowercase, no period                                       |
| Attention flag: high priority    | "{n} high"                                  | e.g. "3 high" — abbreviated, lowercase, no period                             |
| Overview page loading state      | No copy — skeleton cards only               | No "Loading..." text; skeleton conveys loading state                          |
| Overview page error state        | "Could not load overview. Refresh to try again." | `text-sm text-destructive`, inline at top of grid area (loader throw)   |
| No registered tools (impossible in Phase 5) | — | Not applicable — at least todos will always be registered             |

**Accessibility labels** (for screen readers, not visible copy):
- Card `Link` `aria-label`: `"Open Todos tool"` — descriptive enough for screen readers scanning links
- `Circle` icon `aria-label`: `"Not started: {n}"` — set on the wrapper group `aria-label`
- `CircleDot` icon `aria-label`: `"In progress: {n}"`
- `CircleCheck` icon `aria-label`: `"Complete: {n}"`
- `AlertCircle` icon: `aria-hidden="true"` (text already in flag label)
- `ArrowUp` icon: `aria-hidden="true"` (text already in flag label)
- `CheckSquare` title icon: `aria-hidden="true"` (card label covers it)
- `ArrowRight` title icon: `aria-hidden="true"`

Source: 05-CONTEXT.md §Specific Ideas (card mockup). Exact copy: researcher's decision.

## Interaction Contract

| Interaction                              | Behaviour                                                                                               |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Click anywhere on TodoBentoCard          | Navigate to `/todos` via TanStack Router `Link` — no separate click handler needed (D-11)              |
| Keyboard: Tab to bento card              | Card `Link` receives focus; visible focus ring: `focus-visible:ring-2 focus-visible:ring-ring`          |
| Keyboard: Enter/Space on focused card    | Navigates to `/todos` (standard `Link` behaviour)                                                      |
| Hover on bento card                      | Border transitions from `border-border` to `border-primary/50` (150ms ease) (D-10)                    |
| Overview page loads with data            | Route `loader` fetches all `loadData()` functions in parallel; page renders with real counts           |
| Overview page loader error               | TanStack Router `errorComponent` renders error message (see copywriting above)                         |
| Attention row when no flags              | Row is absent from DOM entirely (not hidden with `invisible` or `opacity-0`) (D-04)                   |
| Counts of 0                              | Status badge still renders "0" — shows a zero count, not hidden (card always shows three status groups)|
