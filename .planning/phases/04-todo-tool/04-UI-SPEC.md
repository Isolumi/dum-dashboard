## Spacing Scale

Inherited from Phase 1 contract. No new spacing tokens introduced in Phase 4.

| Token | Value | Usage in This Phase                                                        |
| ----- | ----- | -------------------------------------------------------------------------- |
| xs    | 4px   | Gap between status icon and todo name; gap between priority badge and date |
| sm    | 8px   | Horizontal padding inside priority badge; icon button padding              |
| md    | 16px  | Row horizontal padding (left and right edge); name input internal padding  |
| lg    | 24px  | Page content horizontal padding; top padding above the list                |
| xl    | 32px  | Gap between page heading and list; bottom page padding                     |
| 2xl   | 48px  | Not used in Phase 4                                                        |
| 3xl   | 64px  | Not used in Phase 4                                                        |

**Row height:** 44px minimum (accessibility — touch target requirement from Phase 1 contract).
**Status icon size:** 20px (consistent with Phase 2 nav icon size).
**Trash icon button:** 32px x 32px visible area, `size="icon"` variant, revealed on row hover only.
**Priority badge:** 20px line height, 4px vertical padding, 8px horizontal padding — total height 28px.
**Date text:** 12px, aligned right with `text-muted-foreground`.

Exceptions: None beyond inherited 44px touch target minimum.

Source: Phase 1 UI-SPEC §Spacing Scale (inherited). Row and component dimensions: Claude's Discretion (04-CONTEXT.md).

## Color

Inherited token system from Phase 1 and Phase 2. One new scale token added this phase for the medium priority badge.

| Role             | Token / Semantic Variable     | OKLCH Value             | Usage in This Phase                                                                 |
| ---------------- | ----------------------------- | ----------------------- | ----------------------------------------------------------------------------------- |
| Dominant (60%)   | `--color-neutral-950`         | `oklch(0.09 0 0)`       | Page background (`bg-background`)                                                   |
| Secondary (30%)  | `--color-neutral-900`         | `oklch(0.13 0 0)`       | Not used directly in todo rows (flat list, no cards per row)                        |
| Surface elevated | `--color-neutral-800`         | `oklch(0.20 0 0)`       | Todo row hover background (`hover:bg-neutral-800`); popover/dropdown background    |
| Border           | `--color-neutral-700`         | `oklch(0.28 0 0)`       | Popover border; date input border; list container border (if added)                 |
| Text primary     | `--color-neutral-100`         | `oklch(0.93 0 0)`       | Todo name text; status icon (active states)                                         |
| Text muted       | `--color-neutral-400`         | `oklch(0.60 0 0)`       | `not_started` status icon; "Add a todo..." placeholder; date text; low priority badge text |
| Accent (10%)     | `--color-violet-500`          | `oklch(0.65 0.2 270)`   | `started` status icon (`CircleDot`); focus rings; active input borders              |
| Accent hover     | `--color-violet-400`          | `oklch(0.70 0.2 270)`   | Hover state on status icon click target                                             |
| Destructive      | `--destructive`               | `oklch(0.577 0.245 27.325)` | `high` priority badge background/text; trash icon hover color                  |
| **Amber (new)**  | `--color-amber-400`           | `oklch(0.82 0.17 85)`   | `medium` priority badge background/text only — no other use                        |

**New token to add to `src/theme.css`:**
```css
--color-amber-400: oklch(0.82 0.17 85); /* medium priority badge */
```

This token must be added to the `@theme` block in `src/theme.css` before use. It may not be written as an inline `oklch()` value in any component file (FOUN-01 constraint).

**Accent (`violet-500`) reserved for:**
- `started` status icon color (D-13)
- Focus rings on interactive elements (inherited from Phase 1)
- Active input / inline edit field border highlight

Accent is NOT applied to: priority badges, due date text, row backgrounds, delete icon.

**Priority badge color mapping (D-14):**
- `high` → background `bg-destructive`, text `text-destructive-foreground` — use semantic tokens, no raw value
- `medium` → background `bg-amber-400/20`, text `text-amber-400` — uses new amber token
- `low` → no background, text `text-muted-foreground` — nearly invisible, minimal noise

**Status icon color mapping (D-13):**
- `not_started` → `text-muted-foreground` (neutral-400); icon: `Circle`
- `started` → `text-primary` (violet-500); icon: `CircleDot`
- `complete` → `text-muted-foreground` (neutral-400); icon: `CircleCheck`

**Completed row de-emphasis (D-16):**
- Row: `opacity-60`
- Name text: `line-through text-muted-foreground`

**Hard constraints (inherited, non-negotiable):**
- No hardcoded hex, rgb, hsl, or oklch values in any `.tsx` or `.ts` file.
- No raw Tailwind default palette classes (`gray-*`, `amber-*` if it were a Tailwind default — use the project token only).
- No `dark:` utility prefixes — dark mode only; single theme.

Source: Phase 1 UI-SPEC §Colour (inherited). Priority and status color decisions: 04-CONTEXT.md D-13, D-14, D-16. Amber token: researcher decision per 04-CONTEXT.md §Claude's Discretion.

| Component  | Install Command                          | Usage                                                                 |
| ---------- | ---------------------------------------- | --------------------------------------------------------------------- |
| `popover`  | `bunx --bun shadcn@latest add popover`   | Priority and status dropdowns on click (D-06); date picker container  |

**Priority/status dropdown rationale:** `Popover` is preferred over `Select` for this phase. `Select` triggers a native picker on mobile and adds modal overhead inconsistent with the compact inline-editing model (D-04 through D-07). `Popover` renders a small floating panel anchored to the clicked badge/icon, auto-dismisses on selection, and keeps the interaction inline with the row without a full form mode.

All components are from the shadcn official registry only.

## Layout Specification

### Page Structure (`src/routes/todos/index.tsx`)

```
<main class="flex flex-col gap-xl p-lg">
  <h1 class="text-xl font-semibold">Todos</h1>           ← 20px, weight 600
  <div class="flex flex-col">                             ← list container, no outer border
    <AddTodoRow />                                         ← always visible at top
    {todos.map(todo => <TodoRow key={todo.id} />)}        ← one row per todo
  </div>
</main>
```

### AddTodoRow (D-08 through D-12)

**Collapsed (default) state:**
- Full-width row, 44px height
- Left: `Plus` icon (16px, `text-muted-foreground`) + "Add a todo..." (`text-sm italic text-muted-foreground`)
- No right-side fields visible
- `hover:bg-neutral-800` on the row
- Click or key press activates expanded state

**Expanded (active entry) state:**
- Row expands to show: `Input` (name, flex-1) + priority selector button + date input
- Name `Input`: `text-base`, `border-0 shadow-none focus-visible:ring-1 ring-violet-500`, placeholder "Todo name..."
- Priority selector: compact button showing current priority badge; click opens `Popover` with three options
- Date input: `<input type="date">` styled via `Input` component, width `w-36`
- Tab order: name → priority → date → name (wraps, D-12)
- Enter: submits and creates todo, row returns to collapsed state (D-10)
- Escape: cancels, row returns to collapsed state without creating (D-11)

### TodoRow (D-01 through D-07, D-15 through D-18)

```
[status icon 20px] [name flex-1] [priority badge] [date dot+text] [trash icon — hover only]
```

- Row padding: `px-md py-0` (16px horizontal, vertical centred via `items-center`)
- Row height: 44px minimum (achieved via `min-h-[44px] flex items-center`)
- Row hover: `hover:bg-neutral-800 group` (group class enables `group-hover:` on trash button)
- No border on rows; no card elevation (D-03)

**Status icon (left, D-13, D-15):**
- 20px Lucide icon, clickable as a `Button` with `variant="ghost" size="icon"` (32px touch target)
- Click cycles: `not_started` → `started` → `complete` → `not_started`
- `not_started`: `<Circle size={20} className="text-muted-foreground" />`
- `started`: `<CircleDot size={20} className="text-primary" />`
- `complete`: `<CircleCheck size={20} className="text-muted-foreground" />`

**Name field (center, D-05):**
- Default: `<span>` with `text-base` — plain text, no input chrome
- Click to edit: replace `<span>` with `<Input>` of same width, `autoFocus`, `onBlur` saves, Enter saves, Escape reverts
- Completed state: add `line-through opacity-60 text-muted-foreground` to the span

**Priority badge (right, D-06, D-14):**
- `<button>` styled as badge: `text-sm px-sm py-xs rounded-sm font-medium`
- `high`: `bg-destructive/20 text-destructive`
- `medium`: `bg-amber-400/20 text-amber-400`
- `low`: `text-muted-foreground` (no background)
- Click opens `Popover` with three option buttons; selecting auto-saves (D-06)

**Due date (right, D-07):**
- Default: dot indicator (`•`) + date string in `text-sm text-muted-foreground` (`w-24` fixed width, right-aligned)
- If overdue (past today, status not `complete`): `text-destructive`
- If no date: show nothing (empty space preserved)
- Click to edit: `<input type="date">` via `Input` component, `onBlur` saves, Enter saves

**Delete (far right, D-17, D-18):**
- `<Button variant="ghost" size="icon">` containing `<Trash2 size={16} />`
- Visible only on row hover: `className="opacity-0 group-hover:opacity-100 transition-opacity"`
- Click: calls `deleteTodo` mutation immediately — no confirmation dialog (D-18)
- Hover color: `hover:text-destructive`

### Loading State

While `getTodos` is pending, render 5 skeleton rows:

```tsx
<div className="flex items-center gap-sm px-md min-h-[44px]">
  <Skeleton className="size-5 rounded-full" />          {/* status icon */}
  <Skeleton className="h-4 flex-1" />                   {/* name */}
  <Skeleton className="h-5 w-14 rounded-sm" />          {/* priority badge */}
  <Skeleton className="h-4 w-20" />                     {/* date */}
</div>
```

Render 5 rows. No stagger animation — consistent with existing pattern.

### Empty State

When `getTodos` returns an empty array:

```
[AddTodoRow — always visible]
[empty state block]
  Icon: CheckSquare (32px, text-muted-foreground)
  Heading: "Nothing here yet"  (text-base, text-muted-foreground, weight 400)
  Body: "Add your first todo above."  (text-sm, text-muted-foreground)
```

Centered block, `py-2xl` (48px) vertical padding. No border, no card.

### Error State

When a server function call throws:

**List fetch error** (getTodos fails on mount):
```
Icon: AlertCircle (20px, text-destructive)
Text: "Could not load todos. Refresh to try again."  (text-sm, text-destructive)
```
Inline at the top of the list area. No full-page error.

**Mutation error** (create/update/delete fails):
- Toast-style inline message below the row that triggered the action
- Copy: "Save failed — check your connection and try again."  (text-sm, text-destructive)
- Auto-dismisses after 4 seconds; no dismiss button needed for personal tool

Source: 04-CONTEXT.md §Claude's Discretion (loading/empty/error are researcher's decisions).

## Interaction Contract

| Interaction                          | Behaviour                                                                                                       |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| Click "Add a todo..." row            | Row expands; name `Input` receives focus (`autoFocus`)                                                          |
| Type in collapsed add row            | Row expands immediately; typed character populates name field                                                   |
| Enter in add row (name filled)       | Calls `createTodo`; row collapses to placeholder on success                                                     |
| Enter in add row (name empty)        | No-op — do not submit an empty name                                                                             |
| Escape in add row                    | Row collapses to placeholder; no todo created; any typed values discarded (D-11)                               |
| Tab in add row                       | Moves focus: name → priority selector → date input → name (wraps) (D-12)                                       |
| Click todo name (in list)            | Name text replaced with `Input`, `autoFocus` (D-05)                                                            |
| Blur or Enter on name input          | Calls `updateTodo` if value changed; reverts to `<span>` display (D-05)                                        |
| Escape on name input                 | Reverts to original value without saving (D-05)                                                                 |
| Click priority badge                 | Opens `Popover` anchored to badge with three option rows (D-06)                                                 |
| Select priority option               | Calls `updateTodo`; popover closes; badge updates immediately (optimistic) (D-06)                              |
| Click status icon                    | Cycles `not_started` → `started` → `complete` → `not_started`; calls `updateTodo` (D-15)                      |
| Click due date text                  | Replaces span with `<input type="date">`; `autoFocus` (D-07)                                                   |
| Blur or Enter on date input          | Calls `updateTodo` if value changed; reverts to text display (D-07)                                            |
| Hover row                            | `bg-neutral-800` background; trash icon becomes visible (opacity 0 → 1, 150ms ease) (D-03, D-17)              |
| Click trash icon                     | Calls `deleteTodo` immediately; row removed from list on success (D-17, D-18)                                  |
| Keyboard: focus on trash button      | Trash button is tab-focusable via standard DOM order; Enter/Space activates delete                              |

## Accessibility Notes

- All interactive elements (status icon button, priority badge button, delete button) must have an `aria-label` describing the action including the todo name. Example: `aria-label="Toggle status for 'Buy milk'"`.
- Status icon button `aria-label` must reflect current state: `"Mark 'Buy milk' as started"` when current status is `not_started`.
- `Input` components for inline editing must have `aria-label="Edit todo name"` (or equivalent) since there is no visible `<label>` element.
- Row `role="listitem"` within a `role="list"` container for screen reader semantics.
- Popover trigger buttons must have `aria-expanded` and `aria-haspopup="listbox"`.
