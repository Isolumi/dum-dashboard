Inherited token system from Phase 1 and Phase 4. No new colour tokens introduced in Phase 6.

| Role | Token / Semantic Variable | OKLCH Value | Usage in This Phase |
|------|---------------------------|-------------|---------------------|
| Dominant (60%) | `--color-neutral-950` | `oklch(0.09 0 0)` | Page background (unchanged) |
| Secondary (30%) | `--color-neutral-900` | `oklch(0.13 0 0)` | Not used directly this phase |
| Surface elevated | `--color-neutral-800` | `oklch(0.20 0 0)` | Not used directly this phase |
| Border | `--color-neutral-700` | `oklch(0.28 0 0)` | Not used directly this phase |
| Text primary | `--color-neutral-100` | `oklch(0.93 0 0)` | Not used directly this phase |
| Text muted | `--color-neutral-400` | `oklch(0.60 0 0)` | "Live" dot and label in SUBSCRIBED state; "Reconnecting..." text in degraded state |
| Accent (10%) | `--color-violet-500` | `oklch(0.65 0.2 270)` | Not used for the indicator (see reasoning below) |
| Destructive | `--destructive` | `oklch(0.577 0.245 27.325)` | Not used for the indicator (see reasoning below) |

**Indicator colour rationale:**

The live indicator uses `text-muted-foreground` (`neutral-400`) for both the dot and the text in all states. This is a deliberate low-prominence choice:

- Using `text-primary` (violet) for the dot would compete visually with interactive elements that already use violet as the reserved accent.
- Using `text-destructive` for "Reconnecting..." would alarm the user unnecessarily for a transient network state in a personal tool.
- A muted, uniform treatment keeps the indicator informational without drawing attention away from the todo list itself.
- The pulsing CSS animation on the dot provides sufficient affordance that the channel is active without requiring a colour change.

**Accent (`violet-500`) reserved for (unchanged from Phase 4):**
- `started` status icon color
- Focus rings on interactive elements
- Active input / inline edit field border highlight

Accent is NOT applied to: the live indicator, priority badges, due date text, row backgrounds, delete icon.

**Hard constraints (inherited, non-negotiable):**
- No hardcoded hex, rgb, hsl, or oklch values in any `.tsx` or `.ts` file.
- No raw Tailwind default palette classes in components.
- No `dark:` utility prefixes — dark mode only; single theme.

Source: Phase 1 UI-SPEC §Colour (inherited). Phase 4 UI-SPEC §Color (inherited). Indicator colour: researcher's decision per 06-CONTEXT.md §Claude's Discretion.

## Component Inventory

### No New shadcn Components Required

Phase 6 adds no new shadcn components. The indicator is implemented with Tailwind utilities and a small CSS animation on a native `<span>` element.

### New Hook (not a component)

A custom hook `useTodosRealtime` is extracted to `src/hooks/useTodosRealtime.ts`. This is a plain TypeScript file in the `src/hooks/` directory (already aliased in `components.json` as `#/hooks`). No `-` prefix needed here since `src/hooks/` is not scanned by TanStack Router.

**Hook contract:**

```ts
type ChannelStatus = 'connecting' | 'live' | 'reconnecting';

function useTodosRealtime(onEvent: () => void): ChannelStatus
```

- `onEvent` callback is called on any `postgres_changes` event (INSERT, UPDATE, DELETE) on the `todos` table.
- Returns the current `ChannelStatus` for the indicator to consume.
- Sets up the Supabase channel on mount, tears it down on unmount via cleanup return.
- Channel name: `"todos-realtime"` (fixed string, not parameterised).

Source: 06-CONTEXT.md §Claude's Discretion (hook extraction), §Implementation Decisions D-03.

## Live Indicator Specification

### Placement

The indicator sits inline with the page heading, right-aligned within the heading row:

```
<div class="flex items-center justify-between">
  <h1 class="text-xl font-semibold">Todos</h1>
  <LiveIndicator status={channelStatus} />
</div>
```

This placement puts the indicator at the top of the page where the user can glance at it without it interrupting the list. It does not appear inside the list or below the heading — that would risk being mistaken for an empty state or mutation feedback.

### States

**Connecting (initial page load — before channel is SUBSCRIBED):**
- Render nothing. No indicator shown.
- Rationale: avoids a flash of "Reconnecting..." before the first successful subscription.

**Live (channel status = SUBSCRIBED):**

```html
<span class="flex items-center gap-1 text-sm text-muted-foreground">
  <span class="size-2 rounded-full bg-muted-foreground animate-pulse" />
  Live
</span>
```

- 8px circle (`size-2 rounded-full`), `bg-muted-foreground`
- Tailwind `animate-pulse` produces the pulsing opacity animation (built into Tailwind v4 via `tw-animate-css`)
- Label text: "Live" — `text-sm text-muted-foreground`

**Reconnecting (channel status = CHANNEL_ERROR or channel closed):**

```html
<span class="text-sm text-muted-foreground">
  Reconnecting...
</span>
```

- No dot, just text. Avoids confusion from a pulsing dot when the channel is actually broken.
- Label text: "Reconnecting..." — `text-sm text-muted-foreground`

### Channel Status Mapping

Map Supabase channel callback status strings to the component's `ChannelStatus` type:

| Supabase status string | `ChannelStatus` |
|------------------------|-----------------|
| `"SUBSCRIBED"` | `'live'` |
| `"CHANNEL_ERROR"` | `'reconnecting'` |
| `"TIMED_OUT"` | `'reconnecting'` |
| `"CLOSED"` | `'reconnecting'` |
| (initial — before first callback) | `'connecting'` |

Source: 06-CONTEXT.md D-04, §Specific Ideas. Placement and visual treatment: researcher's decision per 06-CONTEXT.md §Claude's Discretion.

## Interaction Contract

Phase 6 introduces no new user-driven interactions. Realtime is fully automatic — the user takes no action to trigger it. The indicator is purely informational (non-interactive).

| Behaviour | Description |
|-----------|-------------|
| INSERT event fires on `todos` table | `onEvent` callback calls `getTodos()`; `setTodos` updates with fresh data; indicator stays "Live" |
| UPDATE event fires on `todos` table | Same as INSERT |
| DELETE event fires on `todos` table | Same as INSERT |
| User navigates away from Todos page | Component unmounts; `useTodosRealtime` cleanup removes the Supabase channel |
| User navigates back to Todos page | Component mounts again; a new channel is created; indicator starts in "connecting" (invisible) state, transitions to "Live" once SUBSCRIBED |
| Channel enters error or timeout state | Indicator transitions to "Reconnecting..." (no dot, muted text) |
| Channel recovers (re-subscribes) | Indicator transitions back to "Live" (pulsing dot + text) |

Source: 06-CONTEXT.md D-01, D-02, D-03, D-04.

## Accessibility Notes

- The live indicator `<span>` elements are informational only and do not require keyboard interaction.
- The pulsing dot uses a CSS animation (`animate-pulse`) that respects `prefers-reduced-motion` via Tailwind's built-in media query handling in `tw-animate-css`.
- The "Reconnecting..." state uses plain text — no icon-only state that would require an `aria-label`.
- The outer heading row `<div>` has no interactive role and does not require `aria-*` attributes beyond what the `<h1>` already provides.
