    ```typescript
    import { createClient } from "@supabase/supabase-js";
    import type { Database } from "./database.types";

    export const supabaseAdmin = createClient<Database>(
      process.env.VITE_SUPABASE_URL!,
      process.env.SUPABASE_SECRET_KEY!,
    );
    ```

    Key rules:
    - Use process.env (not import.meta.env) for BOTH vars in this file. VITE_SUPABASE_URL is public but using process.env keeps this file's pattern clearly server-only. The value is still available at runtime via process.env in TanStack Start server functions.
    - SUPABASE_SECRET_KEY has no VITE_ prefix — Vite will not inline it into the client bundle. This is the entire point.
    - Do NOT export a default — named export `supabaseAdmin` only, matching the import boundary convention (only *.functions.ts may import from supabase-admin.ts).
    - Do NOT add any "use server" directive — createServerFn handles the server boundary.
    - The non-null assertions (!) are correct here: if either env var is missing at runtime, a crash-on-startup is preferable to a silent RLS bypass failure.
